# realsim — リアルな3D動画を作るための土台

物理シミュレーションで物を動かし、**映像も音もその同じ物理結果から作る**ための制作パイプラインです。
ドミノ倒しに限らず、「物が落ちる・転がる・ぶつかる」動画全般に使えます。

```
シーン定義（Python）
   │
   ├─[1] 物理  MuJoCo で計算 → 全フレームの位置・回転 ＋ 衝突イベント（時刻・強さ・位置・材質）
   │
   ├─[2] カメラ  動いている物を自動で追う／固定／キーフレーム
   │
   ├─[3] 音    衝突イベント1件ごとに音を配置（録音素材 or 合成）→ 定位・残響・環境音・音量調整
   │
   ├─[4] 映像  Blender 5.3（bpy）＋ Cycles。物理の記録をそのまま再生（再計算しない）
   │
   └─[5] 書き出し  FFmpeg：映像＋音＋レンズの質感（周辺減光・グレイン）＋テロップ
```

映像と音が同じ衝突ログから作られるので、**ズレは原理上ゼロ**です（自動チェックで確認します）。

## セットアップ

Python 3.13 と FFmpeg が必要です。

```bash
# Windows（この PC は %LOCALAPPDATA%\Programs\Python\Python313 に 3.13.17 を入れてある）
"$LOCALAPPDATA/Programs/Python/Python313/python.exe" -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # 版は requirements.txt で固定
```

Blender 本体のインストールは不要です（`bpy` パッケージに含まれます）。
作ったシーンを Blender の画面で開いて確認したい場合だけ、Blender 5.3 をインストールして `--save-blend` を使ってください。

## 使い方

```bash
# 下書き品質で全工程（物理→音→チェック→描画→MP4）
.venv/Scripts/python.exe run.py scenes/domino.py

# 見た目の調整：指定した秒の静止画だけ描画（数秒で終わる）
.venv/Scripts/python.exe run.py scenes/domino.py --still 1.0 2.5 --reuse-physics

# 音だけ作る。聴き比べ用の3種類（後述）も書き出す
.venv/Scripts/python.exe run.py scenes/domino.py --audio-only --ab

# 本番品質・縦動画（ショート向け）
.venv/Scripts/python.exe run.py scenes/domino.py --quality final --vertical

# 一部の時間だけ描画
.venv/Scripts/python.exe run.py scenes/domino.py --range 2.0 4.0 --quality preview
```

出力は `out/<シーン名>/` に入ります。

| ファイル | 内容 |
|---|---|
| `<シーン名>_<品質>.mp4` | 完成した動画 |
| `audio.wav` | 最終の音声（48kHz / 24bit） |
| `stems/` | 音の素材別トラック（衝突・擦れ・残響・環境音）。編集ソフトで調整し直す用 |
| `ab_*.wav` | 聴き比べ用（`--ab` のとき） |
| `recording.npz` | 物理シミュレーションの結果（`--reuse-physics` で再利用） |
| `report.json` | 自動チェックの結果と各工程の所要時間 |

### 品質の段階

| 品質 | 解像度 | サンプル数 | このリポジトリを作った環境（4コアCPU、GPUなし）での実測 |
|---|---|---|---|
| `draft` | 640×360 | 16 | 約5秒／フレーム |
| `preview` | 960×540 | 64 | 約40秒／フレーム |
| `final` | 1920×1080 | 384 | 約17分／フレーム（60fps・60秒の動画なら約6週間） |
| `final4k` | 3840×2160 | 384 | — |

**本番品質は GPU がないと現実的ではありません。** GPU（NVIDIA / AMD / Intel / Apple）があれば自動で使います。

## シーンの作り方

`scenes/` に Python ファイルを置き、`build()` 関数で `Scene` を返します。

```python
from realsim.camera import follow_action, static_shot
from realsim.scene import Body, Scene

def build() -> Scene:
    return Scene(
        name="my_scene",
        duration=3.0,
        bodies=[
            Body("table", "box", (1.2, 0.8, 0.04), "wood_table", (0, 0, -0.02), static=True),
            Body("ball", "sphere", (0.03, 0, 0), "steel", (0, 0, 0.3), release_time=0.5),
        ],
        camera_from_recording=lambda rec, sc: static_shot(rec, (0, -0.6, 0.3), (0, 0, 0.03)),
    )
```

- **単位は実寸（メートル・キログラム）** で書きます。大きさが嘘だと、動き方も音の高さも嘘になります
- 形は `box`（直方体）・`sphere`（球）・`cylinder`（円柱）
- 材質は `realsim/materials.py` から選びます。1つの材質が「物理（密度・摩擦・反発）」「見た目」「音」をまとめて持っています
- 中が空洞の物（マグカップ・箱）は `mass=` に実物の重さを書いてください
- `release_time` を指定すると、その時刻まで空中に止めておいてから離します
- カメラは `follow_action`（動いている物を追う）、`static_shot`（固定）、`camera_keys`（キーフレーム）から選べます
- シーンファイルに `AUDIO = AudioSettings(...)`、`POST = PostSettings(...)`、`CAPTIONS = [Caption(...)]` を書くと、音・仕上げ・テロップの設定を変えられます

例として `scenes/domino.py`（ドミノ倒し）と `scenes/tabletop_drop.py`（いろいろな材質の物を机に落とす）があります。

## リアルさのために入れている工夫

### 映像
- **Cycles（パストレーシング）** で光の反射・影・映り込みを物理的に計算
- **角を丸める**：現実に完全に尖った角はありません。全ての箱と円柱に、大きさに応じた丸めを自動で付けます
- **表面のムラ**：色・粗さ・細かい凹凸に必ずわずかなムラを入れています（均一な表面はCGっぽく見える一番の原因）
- **物体ごとの個体差**：同じ材質でも物体ごとに模様の位置と色味を少しずつ変えています。同じ部品が並んでもコピーに見えません
- **木目の向き**：物体の一番長い辺の方向に木目を流します
- **カメラ**：実在のレンズと同じ焦点距離・絞り・被写界深度（ボケ）、180度シャッターのモーションブラー、ごく小さな手ブレ
- **色の変換**：AgX（Blender 4.0 以降の標準）。明るい部分が不自然に白飛びしにくい
- **仕上げ**：周辺減光とフィルムグレイン（レンズとセンサーの特性）

### 音
- **衝突1回ごとに1音**：物理の衝突イベント（時刻・接近速度・位置・材質の組み合わせ）から鳴らします
- **材質の組み合わせごとに違う音**：木×木、木×机、鋼×木、陶器×木 …
- **同じ音の連続を防ぐ**：録音素材は直近に使ったものを避けて選び（ラウンドロビン）、毎回ピッチ ±4%・音量 ±2dB の揺らぎを加えます
- **強さに応じた音量と音色**：速くぶつかるほど大きく、硬いほど・速いほど高い音まで出ます
- **擦れ・転がり**：滑る速さ・転がる速さと押し付ける力に応じて音量が変わります
- **空間**：カメラ（＝マイク）から見た左右の位置、距離による減衰、音の到達遅延、遠い音ほど高音が減る効果
- **部屋**：残響（実在の部屋のインパルス応答を置けばそれを使用）と、ごく小さな環境音（完全な無音は不自然なため）
- **音量規格**：-14 LUFS（YouTube 等の基準）を目標に、トゥルーピーク -1 dBTP 以下に収めます

### 聴き比べ（`--ab`）
| ファイル | 内容 |
|---|---|
| `ab_a_same_sound.wav` | 全ての衝突が同じ音・揺らぎなし・空間処理なし（比較の基準） |
| `ab_b_materials_variation.wav` | 材質ごとの音＋揺らぎ |
| `ab_c_full.wav` | 本番と同じ（＋擦れ・転がり、定位、残響、環境音） |

## 物理エンジンについて（2026-11-14 変更）

元は PyBullet でしたが、未修正の重大な脆弱性（CVE-2025-8854、bullet3 の Issue #4732 が open のまま）があるため MuJoCo 3.17 に置き換えました。

- 1ステップは 0.5ms 以下（60fps なら 1フレーム 34 回以上）。接触ばねの時定数は時間刻みの 8 倍（34 回なら約 4ms）。時間刻みの 2 倍にすると、落とした高さより高く跳ね返った
- めり込みが大きいときは `Scene(substeps=...)` を増やすと、接触も硬くなって減る（tabletop_drop は 68 回で 2.2mm → 1.1mm）
- MuJoCo は2物体の摩擦を「大きい方」、反発を「平均」で合成します（PyBullet の幾何平均とは少し違う）
- ドミノの終点は、大きいドミノ 3 枚（1.3 倍ずつ）で机に倒れて終わります。元の「4 枚・1.4 倍でマグを倒す」は、MuJoCo ではマグ（320g）が倒れず、マグも机の端からはみ出していました（机を 2.0m に広げた）

## 正直な限界（重要）

- **音の良し悪しは人が聴いて判断する必要があります。** 作成者（AI）は音を聴けません。数値（音量・ピーク・映像とのズレ）は自動でチェックしていますが、「自然に聞こえるか」は確認できていません
- **録音素材がない状態の音は合成音です。** モーダル合成という物理に基づいた方法ですが、実物の録音には及ばず、作り物っぽさが残る可能性が高いです。本当にリアルにするには `assets/RECORDING_GUIDE.md` の通りに実物を録音して置いてください
- **素材（HDRI・テクスチャ）がない状態の見た目は手続き的シェーダーです。** 木・金属などはかなりそれらしくなりますが、写真から作ったテクスチャには及びません。`assets/README.md` を参照
- **形は直方体・球・円柱だけです。** マグカップも「中身の詰まった円柱」として描画・計算しています（取っ手・中の空洞なし）。複雑な形を使うには、メッシュ読み込みと凸分解の機能追加が必要です
- **物理エンジンの誤差**：小さい物や速い物はめり込みや不自然な跳ね方をすることがあります。自動チェックで検出したら `substeps` を増やしてください
- **音量**：まばらな衝突音だけの動画は、リミッターで強く潰さないと -14 LUFS に届きません。初期設定では音の粒立ちを優先してリミッターを 6dB までに制限しているため、目標より小さく書き出されることがあります（`report.json` に記録されます）。`AudioSettings(max_limiting_db=...)` で変えられます

## ファイル構成

```
run.py                     実行スクリプト
realsim/
  scene.py                 シーンの記述（物体・カメラ・環境）
  materials.py             材質表（物理・見た目・音）
  physics.py               MuJoCo シミュレーションと衝突イベントの記録
  camera.py                自動カメラワーク
  render/blender_render.py Blender への読み込み・照明・描画設定
  render/looks.py          手続き的マテリアル
  audio/synth.py           衝突音・擦れ音の合成
  audio/samples.py         録音素材の読み込みとラウンドロビン
  audio/mixer.py           配置・定位・残響・環境音・音量調整
  post.py                  FFmpeg による書き出し
  qc.py                    自動チェック
scenes/                    シーンの例
assets/                    素材を置く場所（README と録音ガイドあり）
tests/                     物理・音・チェックのテスト（python -m pytest tests）
```
